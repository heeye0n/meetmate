## 1. 5W1H

| 항목 | 내용 |
|---|---|
| **Why (문제)** | ① 팀원마다 수업·알바 시간이 달라 **회의 시간 잡기**에 단톡방에서 수십 개 메시지가 오간다. ② 회의를 해도 "누가, 무엇을, 언제까지"가 회의록 속에 묻혀 **할 일이 흐지부지**된다. ③ 결정 사항이 실제 작업(이슈)으로 옮겨지지 않아 마감 직전에 몰린다. |
| **Who (사용자)** | 3~6인 대학 팀프로젝트 팀. 특히 회의록을 맡은 팀원·팀장. (내 경험: 정보시스템 팀 프로젝트 회의록·레드마인 이슈 관리) |
| **What (제품)** | 카톡 대화에서 가능한 시간을 뽑아 회의 시간을 추천하고, 회의록에서 할 일·담당자·마감일을 근거와 함께 뽑아 GitHub Issues로 등록하는 웹앱 |
| **When** | 회의 전(약속 잡기), 회의 직후(회의록 정리), 평소(대시보드로 진행 확인) |
| **Where** | 로컬 웹 브라우저 (Streamlit, `localhost:8501`) |
| **How** | Python + Streamlit, LLM API(OpenRouter 무료 모델 또는 학교 팩트챗 게이트웨이), 로컬 JSON 저장, GitHub REST API, Claude Code(서브에이전트·커스텀 명령어·MCP)로 개발 |

## 2. 기존 방식의 한계

- 단톡방 투표/when2meet: 링크를 따로 만들고 모두가 들어와 칸을 칠해야 함 → 실제로는 카톡으로 "나 화 3시 이후 돼"라고 말하고 끝남
- 일반 회의 요약 앱(클로바노트 등): 요약까지만 해 주고 **담당자·마감·이슈 등록**으로 이어지지 않음
- 생성형 AI에 그냥 맡기면: 말하지 않은 담당자·날짜를 지어냄(할루시네이션)

## 3. 핵심 기능 (5개)

### F1. 약속 잡기 — 카톡 대화 → 가능 시간 → 회의 시간 추천 ⭐ 차별 기능
- 입력: ① 카톡 대화 붙여넣기 ② 또는 팀원별 주간 시간표 그리드에 직접 체크
- AI 역할: 대화에서 **팀원별 가능/불가능 시간만 구조화(JSON)** 해서 추출 ("화요일 3시 이후" → `{"member":"민수","day":"TUE","start":"15:00","end":"22:00","type":"available","evidence":"나 화 3시 이후 돼"}`)
- 코드 역할: 교집합 계산과 순위는 **AI가 아니라 Python 코드로** 계산 (계산을 LLM에 맡기지 않음 → 정확성 보장)
- 출력: 전원 가능한 시간 Top 3 (없으면 "1명 빼고 가능한 시간" + 빠지는 사람 표시), 히트맵, `.ics` 파일 다운로드(구글/삼성 캘린더 등록)
- 사용자가 AI 추출 결과를 표에서 수정한 뒤 계산 (사람 검토 단계)

### F2. 회의록 → 액션 아이템 추출 (근거 표시)
- 입력: 회의록 텍스트 붙여넣기 / `.txt` `.md` 업로드
- 출력 표: 할 일 · 담당자 · 마감일 · 우선순위 · **원문 근거 문장**
- 규칙: 회의록에 없는 담당자/날짜는 `미정`으로 둔다. 근거 문장이 원문에 실제로 존재하는지 **코드로 검사**하고, 없으면 ⚠️ 표시
- "다음 주 금요일" 같은 상대 날짜는 회의 날짜 기준으로 코드에서 계산

### F3. 검토 후 GitHub Issues 등록
- F2 표를 사용자가 수정·선택 → 버튼 한 번으로 팀 저장소에 이슈 생성 (제목, 본문에 근거 문장, assignee 매핑, 마감일 라벨)
- 토큰 없을 때는 "Markdown 체크리스트 복사" 대체 기능 (시연 실패 대비)

### F4. 팀 대시보드
- 팀원별 할 일 수 / 완료율, 마감 임박(3일 이내) 목록, 회의 이력
- 다음 회의 추천: 가장 가까운 마감일 이전으로 F1 결과와 연결

### F5. 회의 이력 저장/불러오기
- 회의별(날짜, 참석자, 결정 사항, 액션 아이템)을 로컬 JSON에 저장
- 지난 회의의 미완료 할 일을 다음 회의 안건으로 자동 제안

## 4. 비기능 요구사항

- API 키·GitHub 토큰은 `.env`에서만 읽고 `.gitignore`로 제외 (코드에 하드코딩 금지)
- LLM 제공자 교체 가능: `.env`의 `LLM_PROVIDER=openrouter|factchat`, `LLM_MODEL=...`
- LLM 응답은 반드시 JSON 스키마 검증 → 실패 시 1회 재요청 → 그래도 실패 시 오류 안내 (앱이 죽지 않음)
- 무료 API 한도(분당/일일 요청 수)를 고려해 같은 입력은 캐시
- 한국어 UI, 모바일이 아닌 노트북 화면 기준

## 5. 기술 스택 / 구조

```
MeetMate/
├── app.py                 # Streamlit 진입점 (페이지 이동)
├── views/                 # home.py, schedule.py, minutes.py, dashboard.py (st.navigation, 영어 파일명)
├── core/
│   ├── llm.py             # LLM 호출 (provider 교체, JSON 검증, 재시도, 캐시)
│   ├── schedule.py        # 가능 시간 교집합·순위 계산 (순수 Python, 테스트 대상)
│   ├── actions.py         # 액션 아이템 추출, 근거 검증, 상대 날짜 계산
│   ├── github_issues.py   # GitHub REST API
│   └── storage.py         # JSON 저장
├── data/                  # 로컬 저장소 (gitignore)
├── samples/               # 시연용 샘플 카톡/회의록
├── tests/                 # pytest (schedule, actions)
└── docs/                  # PRD, 단계별 프롬프트, AI 협업 기록
```

## 6. AI 활용 계획 (평가 25점)

| 단계 | 사용 도구 | 활용 방식 |
|---|---|---|
| 기획 | Claude Code | PRD 작성, 단계별 프롬프트 분해 (`docs/prompts/`) |
| 구현 | Claude Code + CLAUDE.md | `PRD_stepN.md를 실행해` 방식으로 단계별 구현 |
| 기록 | 커스텀 명령어 `/log` | 단계마다 프롬프트·결과·내 판단을 `docs/ai-log/`에 자동 기록 |
| 리뷰 | 서브에이전트 | code-reviewer(읽기 전용) → fixer → ux-advisor 협업 |
| 테스트 | pytest + Playwright MCP | 계산 로직 단위 테스트, 브라우저 자동 E2E 테스트 + 스크린샷 |
| 배포/보관 | GitHub MCP 또는 git | `heeye0n/MeetMate` 저장소 |
| 앱 내부 | LLM API | 카톡 → 시간 JSON, 회의록 → 액션 아이템 JSON |

## 7. 예상 난관과 대응

| 난관 | 대응 |
|---|---|
| LLM이 시간을 잘못 해석 ("저녁" = 몇 시?) | 해석 규칙을 프롬프트에 명시(저녁=18~22시 등) + 근거 문장 표시 + 사용자 수정 표 |
| LLM이 담당자/날짜를 지어냄 | `미정` 규칙 + 근거 문장 원문 대조 코드 검사 |
| 무료 모델 중단·한도 초과 | `.env`로 모델/제공자 교체, 캐시, 샘플 응답으로 오프라인 시연 모드 |
| 시연 중 네트워크 오류 | 오프라인 데모 모드 + 녹화 영상 준비 |
| 크레딧 부족 (Claude Code) | 기본 Haiku, 어려운 오류만 Sonnet, 작업 단위로 `/clear` |
